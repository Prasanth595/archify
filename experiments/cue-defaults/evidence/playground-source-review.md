# CUE playground identity and evaluation scope

**Best supported read-only identity:** use the actual playground header's **Menu** (vertical dots); pinned [header.tsx](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/src/components/header.tsx) renders `CUE {CUEVersion}` there. Record what the live menu actually displays and the time. In this fixed source the generated [version constant](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/src/config/gen_cuelang_org_go_version.ts) and [go.mod](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/go.mod) both say v0.17.0, but this establishes the pinned source, not the deployed build. The frontend string is a generated label, not independent verification of actual WASM bytes or exact repository commit. No documented engine-version method was found in the inspected [WASM entry](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/main.go); no undocumented global needs to be called. WASM build metadata was not inspected and is not claimed present. A live binary hash and independently inspected build metadata would be needed to bind exact engine build; no download/execution was done here.

**Mode semantics:** the fixed [implementation](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/impl.go) executes CUE Go API in WASM, not a CLI invocation. It accepts CUE/JSON/YAML input from one stdin string in a synthetic `example.test` module, with language version from the CUE Go dependency. `eval` adds `cue.Final()` to syntax generation to select defaults but deliberately does not validate with Final; `export` validates `cue.Concrete(true)` and then encodes the chosen format; `def` uses base syntax options without those additions. Input/output format and complete UI state therefore matter. The implementation says it emulates the essence of cmd/cue, not byte-for-byte CLI equivalence; the issue's `cue eval -e` selection, multi-file module contexts, CLI flags, exits and diagnostics are not established by a single UI mode. Label observations `playground eval/def/export`, preserve exact full output and input, and distinguish any external CLI execution.

Upstream [full tests](https://github.com/cue-lang/cuelang.org/blob/957f004c34a71982b5773e86126d9df2a5c6d48f/playground/impl_test.go) explicitly expect `foo: int | *3` to remain disjunctive in def but become `foo: 3` in eval/export, and incomplete `foo: int` to error in export. These are upstream expectations, not tests run now and not proof of issue #1449's runtime behavior.
