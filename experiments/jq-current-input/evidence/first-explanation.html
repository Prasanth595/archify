jq 的 `.` 此刻指向谁？

长图

答

结论

as 绑定一个值后，后续表达式仍接收绑定前的输入。普通管道则把左侧输出传给右侧。找不到负责人时，先检查 . 指向谁。

  1. 两种正确写法输出相同，但构造结果前的 . 不同。1
  2. 错误写法也可能退出成功，却把负责人变成 null。1
  3. jq 手册已经解释这条规则；下图把四组观测放在一起。2

A 与 B：同一份输入，两次独立运行

图的结构
  • 整份输入 root
  • 绑定后仍是 root kept
  • 每次一项 job jobs
  • Mina 与 Bo names
  • 管道后仅有 owners replaced
  • 无 jobs，报错 fail
  • jobs → names · 变量查表
  • kept → jobs · .jobs[]
  • replaced → fail · .jobs[]
  • root → kept · as
  • root → replaced · 管道

图上的两条路线是两个查询的对照，不是一次执行中的条件分支。root 表示含 owners 和 jobs 的整份输入。3

  1. 整份输入 ↗

    owners 把 u1、u2 映射到 Mina、Bo；jobs 中有 compile、test 两项任务。

  2. 绑定后仍是 root ↗

    A 将映射绑定给 $owners；观测点上的当前值仍包含 owners 和 jobs。

  3. 每次一项 job ↗

    .jobs[] 分别产生 compile 和 test。此时 .owner 是 u1 或 u2；$owners 仍可用。

  4. Mina 与 Bo ↗

    $owners[.owner] 用当前任务的 owner 查已绑定映射，得到两个名字。

  5. 管道后仅有 owners ↗

    B 的 .owners 把当前输入变成映射，只剩 u1 和 u2 两个键。

  6. 无 jobs，报错 ↗

    该映射没有 jobs 字段，.jobs 为 null；.jobs[] 报错，退出码为 5。

2

每条查询实际运行了什么？

A 保存映射，随后逐项读取任务。4

B 把当前输入直接换成映射。5

C 每次绑定一个任务，让当前输入继续保留整份数据。6

D 切到任务后，又试图从当前任务里读 owners。7
