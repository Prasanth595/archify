# Rust ownership: source reading, not a new experiment

2026-10-27. **Decision: defer the content experiment; reject an importer or shared Viewer change.** The candidate question is concrete: after `let moved = b`, did the `String` owner move, or did the mutable reference binding move? A source-anchored explanation could distinguish owner `s`, reference `b`/`moved`, and the underlying loan. But the fixed upstream tools already show substantially more than a generic ownership graph, and the available snapshot contains a discrepancy that needs interpretation before it could support a reliable new diagram. No evidence yet shows an Archify reader needs this additional view or that it improves understanding.

## Duplicate and method

Read local `audit/prior-experiments-20261027.json` and historical `origin/codex/research-lab-20261025` scouts, including `type-reading-round8`, `round19-control-data-reading`, and `round20-state-lifetime-reading`. Aquascope and RustViz were already pinned in type-reading; Static uses covers source use versus execution, and Maybe initialized covers RustOwl's static path-state union, not a single runtime state. This candidate would concern movement of a *reference* versus movement or destruction of its referent; it is adjacent but not a replacement for those cases. A new fixture alone does not establish distinct value.

Used read-only shallow Git checkouts, exact source and committed snapshots; no browser, installs, compilation, test execution, upstream execution, commit or push. Historical and upstream results are not this machine's test results. Repository [CONTRIBUTING](../../../../CONTRIBUTING.md), [REVIEWING](../../../../REVIEWING.md), and Archify review skill were consulted. Source links below pin complete revisions.

## Native baseline and actual evidence

- [Aquascope `f2d0a06034b86765a91f10b7c8e40ec31ecb87a6`](https://github.com/cognitive-engineering-lab/aquascope/tree/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6), [MIT license](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/LICENSE): the project supplies compiler permission analysis **and** an interpreter for runtime state, plus mdBook integration; these are separate evidence modes. Its [permission implementation](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/src/analysis/permissions/output.rs) joins conflicting paths with live loans to refine write/drop permissions, and further filters to mutable loans for read refinement. A loan is an analysis entity, not another owner or a runtime object. Its pinned [toolchain](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/rust-toolchain.toml) is nightly-2026-05-01 with rustc-dev and Miri; README release setup refers to a different older release toolchain, so do not mix them.
- The complete [moved_0.test](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/tests/boundaries/moved_0.test) has `s`, `b = &mut s`, `moved = b`, `moved.push_str("b")`, and a subsequent `b.push_str("c")`. It is a borrow-checking case, not a successful runtime trace. Its committed [boundary snapshot](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/tests/snapshots/boundaries__bar%40moved_0.test.snap) records source locations, expected and actual permission fields, with `path_moved: 0` at line 5, column 3. At line 2 column 15 its expected drop is false while actual is true: these fields must remain distinct, not silently converted to an agreed ground truth. [Harness](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/tests/boundaries.rs) sorts boundaries and snapshots the returned state; a snapshot pass asserts recorded output, not agreement between every `expected` and `actual` value. A future controlled reproduction could run `cargo test -p aquascope --test boundaries` from the pinned checkout with its specified toolchain and dependencies; this runs the harness over the boundaries directory, not just this one fixture. No such run was made here. Separately, [interpreter basic input](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/tests/interpreter/basic.test) and its [snapshot](https://github.com/cognitive-engineering-lab/aquascope/blob/f2d0a06034b86765a91f10b7c8e40ec31ecb87a6/crates/aquascope/tests/snapshots/interpreter__basic.test.snap) record stack frames and integer locals for a different program. They cannot establish the heap or runtime execution of `moved_0`.
- [RustViz `dfd4d0e7a4a3b4beddac50a85902a38af85230f0`](https://github.com/rustviz/rustviz/tree/dfd4d0e7a4a3b4beddac50a85902a38af85230f0), [root MIT license](https://github.com/rustviz/rustviz/blob/dfd4d0e7a4a3b4beddac50a85902a38af85230f0/LICENSE): the current compiler-integrated rewrite offers a playground, CLI standalone HTML, mdBook and library with source/timeline SVG and hover text. [Data model](https://github.com/rustviz/rustviz/blob/dfd4d0e7a4a3b4beddac50a85902a38af85230f0/rustviz-plugin/src/svg_generator/data.rs) explicitly includes move, mutable/static borrow and return, owner drop at reassignment, branch histories and resource-moved state. The [book's ownership example](https://github.com/rustviz/rustviz/blob/dfd4d0e7a4a3b4beddac50a85902a38af85230f0/mdbook-rustviz/test-book/src/ownership.md) already discusses move versus later drop, with linked source/timeline SVGs and hover. Its [borrowing chapter](https://github.com/rustviz/rustviz/blob/dfd4d0e7a4a3b4beddac50a85902a38af85230f0/mdbook-rustviz/test-book/src/borrowing.md) discusses owner, reference, live loan, implicit borrowing and non-lexical lifetimes. [nll_two_borrows.rs](https://github.com/rustviz/rustviz/blob/dfd4d0e7a4a3b4beddac50a85902a38af85230f0/rustviz-plugin/tests/nll_two_borrows.rs) is a complete native Rust fixture with two sequential mutable references and uses; it is not a separately verified visualization or test result. This version's source handles branches; do not claim the older annotation-based version's limitations as the current baseline. Vendored assets need their own license checks before reuse.

## Revisit only with a discriminating reading task

A minimal future experiment would use existing Archify Explainer, pinned full input and an explicitly authored table: source binding / referent / loan / source location, alongside the original Aquascope output and RustViz native source-and-timeline view. Mark static analysis, authored interpretation, and any separately observed runtime steps distinctly. Do not label `moved = b` as destruction of `s`, loan termination, or a heap trace. Preserve the full original MIT notice if copying substantial source and verify any bundled assets separately.

Before prototyping, resolve the snapshot discrepancy from the producer and locate a complete corresponding native output or rerun it in a controlled environment; use a valid example if comparison requires actual execution. Form a fixed task asking which binding moves, who owns the `String`, and whether a source annotation proves runtime destruction. Compare upstream native experience and an Archify explanation with the same source, without hiding hover or native capabilities. Reject if the native tools already answer at least as clearly, if the table adds no independently supported fact, if it conflates static and runtime evidence, or if it requires a custom compiler backend to be accurate. Record all attempts and uncertainty; no claim of faster reading, adoption, or human benefit without a comparative study. Current result does not justify implementation.
