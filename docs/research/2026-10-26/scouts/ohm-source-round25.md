# Ohm editor source audit, 2026-10-28

**Scope and decision:** continuation of existing grammar-reading-smalltools, not a new generic importer. Source-only; no execution or browser observation. Compare the actual deployed editor separately: the observed deployed parser reports `window.ohm.version` 17.5.0; the deployed editor commit is unknown, so do not equate it to the pinned source below. Defer a new artifact until the native UI observation identifies an actual remaining reading question.

**Natural example.** [Ohm issue #254](https://github.com/ohmjs/ohm/issues/254) gives the complete grammar `X { X = A | B  A = "a"  B = "a" "b" }` and input `ab`. The author proposes `X = A end | B end`; a maintainer proposes `B | A`. The author explicitly says their real application is not prefix-shaped. Those comments are two proposed changes to this example, not evidence that every real grammar can be corrected by reordering. The question is why the first successful alternative does not yield the complete match the author expected. No native output for this case is asserted here.

**What the source establishes.** [index.js](https://github.com/ohmjs/ohm-editor/blob/2ff2a07225031ead520ad22c2bc19bac7ce75ff2/src/index.js) automatically enables `showFailures` when the whole input fails and disables it when it succeeds, initially and after grammar/input changes; explicit user toggling overrides until the next change. Thus “failed nodes always hidden by default” would be false for the failing overall example. [trace-element.vue](https://github.com/ohmjs/ohm-editor/blob/2ff2a07225031ead520ad22c2bc19bac7ce75ff2/src/components/trace-element.vue) filters failed children and their subtrees when `showFailures` is off; when on, failed choice children are visually distinguished. The initial-collapse rule applies only to labeled non-leaf failed nodes: `initiallyCollapsed` first returns false for unlabeled nodes and leaves, then returns true for failures. Sequence and alternative nodes are unlabeled and therefore do not collapse under that rule; failed leaf labels likewise remain visible. Implicit spaces can also be filtered. Sequence/alternative nodes have no label, and successful nodes with no bindings have no label; unlabeled does not necessarily mean unattempted. Collapsed descendants are not rendered until expansion. Hover on expressions with source scrolls the grammar editor, and clicking non-leaf nodes toggles collapse. [timeline.js](https://github.com/ohmjs/ohm-editor/blob/2ff2a07225031ead520ad22c2bc19bac7ce75ff2/src/timeline.js) tracks rendered labeled nodes and maps rightmost failures to steps; stepping hides later elements. A node absent from a view can therefore be filtered, collapsed, unlabeled, or not yet visited in timeline; it is not proof of a skipped attempt. Conversely, the source reviewed here does not establish an explicit “skipped” status or prove exactly which nodes are generated for issue #254.

**Observed live case (reported by root; not independently rerun):** `/tmp/archify-round25-ohm/scoped-end-explained-state.json` and `.png` record `X = A end | B end`. The successful parse defaults Explain parse off; switching it on immediately displays successful A and `"a"`, failed `end`, and B/`"a"`/`"b"`/`end`, without manual expansion. This observation is consistent with the conditional collapse rule above; it does not verify the deployed editor SHA.

**Strong native baseline:** Ohm's [official API](https://ohmjs.org/docs/api-reference) provides `g.trace()` and text summary of parsing steps; [README](https://github.com/ohmjs/ohm/blob/main/README.md) demonstrates a full success/failure text trace alongside the interactive editor. Assess the deployed editor with the original input, its failure toggle, expansion, timeline and linked grammar source before attributing a missing question to the native tool. Source review alone cannot establish actual deployed presentation or UX.
