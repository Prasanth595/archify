Further independent blockers from inspecting the complete source and parser: two bare `varchar` fields require a parenthesized length in this adapter; `username [not null]` is a non-PK/non-FK constraint with no native ERD attribute property; `created_at [default: ...]` is not accepted or represented. The native ERD attribute schema has only `name`, `type`, `key`, `references`, with `additionalProperties: false`; directly attaching structured default or general nullability is invalid. A fixed, explicitly authored textual card listing `users.username NOT NULL` and `users.created_at DEFAULT now()` could communicate both as *source evidence* alongside native entities, without executing the expression or falsely claiming round-trip DDL. Such a presentation is a potential bounded manually authored comparison, not an existing structured semantic contract, generic import or proved equivalent; it needs visible per-column attribution and a test that nothing is silently dropped. Supporting arbitrary defaults and syntaxes in the adapter requires explicit grammar, escaping, limits and representation contract, with nontrivial maintenance. A generic parser or schema change is not justified by this single example.

## Native baseline and falsifiable next step

The [official @dbml/core API](https://dbml.dbdiagram.io/js-module/core/) documents `Parser.parse(str, format)` returning a Database model and exporter APIs; current documentation prefers `dbmlv2` over deprecated `dbml`. The upstream [Playground project](https://github.com/holistics/dbml/tree/0c34d8514ae7ebb457549531ef4fa5dab839c4fa/dbml-playground) includes this file. This is documented capability, not a run of that exact pinned package against the fixture; API docs are rolling and may differ from the pinned revision. Nothing here demonstrates that native DBML fails to expose the same facts or that an Archify rendering is faster.

Smallest next comparison: on a fixed, inspectable official package/version, use the identical full 127 bytes in its native Playground/parser model and a manually authored existing Archify ERD plus clearly attributed constraint notes; record full input, source revisions, native output, semantic checklist (PK, unique, both bare types, NOT NULL, default literal), screenshots, and first-draft/repair actions. Ask a specific reader to identify which column is required and which has the default, without claiming a user study from one run. If the native view already answers as well, the Archify view obscures a fact, or the required manual transcription outweighs readability, stop: no adapter expansion. If it adds observable value, use a separate scope decision for preserving arbitrary constraints; retain source-backed checks and reject unrepresentable syntax. No implementation, execution, browser, test, or installation was performed in this investigation.
