# Compiler Explorer optimization remarks: AnalysisFPCommute filter

**Source conclusion:** In fixed Compiler Explorer `1fbdacb205156f4f5f19686cbd688c093e887751`, an otherwise accepted LLVM YAML `!AnalysisFPCommute` record is normalized to `Analysis`, not silently excluded because its original tag differs. The fresh Opt Viewer template defaults **Show analysis opt-remarks off**, so such a record is not displayed until that filter is enabled; restored pane state can override the template default. Source-only inference, not proof that the live deployment has this revision, that the compiler emits this exact remark, or that a given record passes other filters.

[Parser, `lib/base-compiler.ts`](https://github.com/compiler-explorer/compiler-explorer/blob/1fbdacb205156f4f5f19686cbd688c093e887751/lib/base-compiler.ts): `processRawOptRemarks` parses all YAML documents, skips documents with parse errors and entries whose `DebugLoc.File` does not include the compile filename, and deduplicates using JSON of the parsed record. It strips the tag's leading `!`; names beginning `Missed` or `Passed` are mapped to those respective classes, while every other tag maps to `Analysis`. It derives display text from `Args`. Thus the distinct original subtype is not preserved in `optType`; same parsed-record dedup may independently remove a duplicate. Parsing and file/location qualification must hold.

[Viewer, `static/panes/opt-view.ts`](https://github.com/compiler-explorer/compiler-explorer/blob/1fbdacb205156f4f5f19686cbd688c093e887751/static/panes/opt-view.ts) accepts only remarks with `DebugLoc` and an enabled matching `Missed`, `Passed`, or `Analysis` boolean.
